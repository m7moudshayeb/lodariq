Date: 2026-08-24

Status: Planned backlog generated from the 2026-08-24 visual and manual audit. These are executable manual scenarios to add to automated coverage later.

This document deliberately contains 540 explicit cases. The cases are organized as a launch matrix rather than a test-suite command: execute targeted scenarios first, capture the same viewport and state before and after a change, and do not run the full repository suite unless a change spans the entire product.

## Execution protocol

1. Start only the required API, dashboard, and fixture-host processes for the scenario family.
2. Use the Codex in-app browser for every visual assertion. Capture the same viewport, route, theme, and data state before and after a change.
3. Before every click or typed interaction, take a fresh DOM snapshot. After the action, take the cheapest state check that answers the question; capture a screenshot when visual confirmation matters.
4. Record Pass, Fail, Blocked, or Not run, plus a screenshot path and a concise defect reference.
5. For mutation scenarios, use disposable fixture values. Never place real credentials, tokens, personal contact data, or customer data into the browser.
6. Keep dashboard, creator chrome, and customer Brand Theme observations separate. A visually pleasing state is not evidence that release, tenant isolation, or credential handling is correct.

## Status and priority

- P0: launch blocker or security/data-integrity risk.
- P1: core flow broken, misleading, or visually unusable.
- P2: important polish, accessibility, or resilience gap.
- Planned: scenario has not been converted into a durable automated test.
- Existing observations from this run are listed after the matrix; they do not mark every case as passed.
