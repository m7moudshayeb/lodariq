The install

The developer's entire job

One script tag, added once, before </body>. It stays invisible to your users until something is published, and it never changes again — new tours, edits, translations and rollbacks all ship without touching it.

index.html 
<script async src="https://cdn.lodariq.io/lodariq.js"
  data-workspace="wk_your_workspace"
  data-env="production"></script>

How it works

Idea to production, without leaving your product

  1. 1

    Install the snippet

    Paste the script tag once. No browser extension, no staging-only build, no code for anyone to maintain afterwards.

  2. 2

    Create on the live product

    On staging, press ⌘⇧L. The editor opens on the page itself — each step is written next to the thing it points at.

  3. 3

    Verify on staging

    Publishing compiles an immutable, content-addressed artifact. You review it exactly as your users will see it — same bytes, same theme.

  4. 4

    Promote the exact artifact

    Production receives the artifact you verified — not a re-build, not a copy. Rollback is one pointer move to a version that already existed.

Why Lodariq

What the category gets wrong, on purpose

Every established tool in this space eventually hands you a CSS editor and calls it no-code. Lodariq is built so that escape hatch never needs to exist.

One surface

Authoring, targeting, theming, review and release all happen on your page. There is no second application where tours are described in the abstract and broken in the concrete.

No code after install

Steps anchor to elements by role, accessible name and context — the way a person finds them. There are no selectors to write, so there are no selectors to go stale.

Releases you can trust

Staging and production run pinned, immutable artifacts. When your UI changes, Lodariq shows you which steps need attention — before your users find out for you.
